# Quality Gates — 逐门禁检查清单

> 用法：Chief 在门禁前按 Track 选取对应清单；任何未满足项必须有 owner、关闭条件、风险接受记录。

## G0 Intake

- [ ] 用户原话已保留，没有改写目标；
- [ ] 目标一句话说清“交付什么、给谁、解决什么问题”；
- [ ] Track 已判定，理由记录；
- [ ] 范围/非范围明确；
- [ ] 成功指标可度量；
- [ ] 约束（技术/合规/预算/时间/环境）记录；
- [ ] 假设/初始风险有 owner；
- [ ] 需要用户决定的 L3 项已识别；
- [ ] `.ai-team/state/PROJECT.md` 已写。

### G0.1 仓库基线（新项目或基线缺失时）

- [ ] `git init` / 默认分支（通常 `main`）；
- [ ] `.gitignore` 覆盖依赖、构建产物、缓存、`.env`/密钥、日志、临时文件；
- [ ] `.gitattributes` 统一换行符/二进制/语言统计；
- [ ] `.editorconfig`、`.gitmodules`、`.git-blame-ignore-revs`（如适用）；
- [ ] 初始提交；
- [ ] remote/分支保护/规则集（首次 push 需用户批准）；
- [ ] 密钥扫描、依赖扫描、CI 骨架；
- [ ] 仓库内无真实密钥/凭据/大文件。

## G1 Product

- [ ] 问题陈述不是功能清单；
- [ ] 用户/角色/场景清楚；
- [ ] FR/NFR 有 ID、行为、验收、优先级；
- [ ] 验收标准可测试；
- [ ] 异常/权限/空态/并发/数据生命周期覆盖；
- [ ] 范围/非范围/MVP 明确；
- [ ] 优先级有方法（RICE/MoSCoW/Kano）与理由；
- [ ] 追踪矩阵初稿；
- [ ] 开放问题有 owner/截止；
- [ ] 产品经理没有越权指定技术方案；
- [ ] Chief 已接受（不是自批）。

## G2 Design

### UX（涉及界面时）

- [ ] 用户旅程/IA/关键任务；
- [ ] 页面/组件清单；
- [ ] 状态完整（loading/empty/error/partial/disabled/无权限）；
- [ ] 响应式/断点/触控尺寸；
- [ ] 设计 token（颜色/间距/字体/圆角/阴影）；
- [ ] WCAG 2.2 AA：键盘/焦点/对比度/语义/减少动效；
- [ ] 微文案/错误信息；
- [ ] 开发交接验收清单。

### Architecture

- [ ] C4 Context/Container/Component；
- [ ] 模块边界/依赖方向/数据所有权；
- [ ] 数据模型/索引/迁移/保留；
- [ ] API/事件契约/错误模型/版本；
- [ ] 失败模式/超时/重试/幂等/降级/补偿；
- [ ] 认证/授权/租户/密钥/审计/隐私；
- [ ] NFR 预算/容量/成本；
- [ ] 部署拓扑/环境/发布/回滚；
- [ ] 可观测性；
- [ ] ADR（含被否决选项）；
- [ ] TBD 有验证计划。

### Cross-review

- [ ] 产品经理确认需求覆盖；
- [ ] UX 确认可实现/状态完整；
- [ ] 架构确认契约无歧义；
- [ ] QA 确认可测试；
- [ ] 安全确认威胁模型；
- [ ] 凭据/迁移/传输/租户边界设计有 `SEC-*` 预审；
- [ ] DevOps 确认可部署/可回滚；
- [ ] 结论写入 `STATUS.md`。

## G3 Plan

- [ ] 每个 FR/NFR 映射到任务/测试；
- [ ] 任务有 ID/owner/依赖/验收/证据；
- [ ] 装配清单完整（Bean/仓储/外部依赖/配置键/迁移）；
- [ ] 同模块连续未审切片 ≤2；
- [ ] 文件所有权切分，无并行冲突；
- [ ] 关键路径/并行路径清楚；
- [ ] 风险/阻塞/回退计划；
- [ ] DoR 满足；
- [ ] `TASKS.md` 已写。

## G4 Build

- [ ] 只改任务范围；
- [ ] 启动实现任务前 `checkpoint-check` 未到期；
- [ ] 代码符合设计/契约；
- [ ] 契约变更与实现同一提交，并更新 `API-CONTRACTS`/ADR + 契约测试；
- [ ] 装配点/仓储/外部依赖/配置键已接，不是“写完未接线”；
- [ ] lint/typecheck/build 通过；
- [ ] 单元测试通过；
- [ ] 测试报告有唯一全量基线（命令/总数/skipped/commit）；
- [ ] 新增逻辑有测试；
- [ ] 数据迁移可回滚/兼容；
- [ ] 无硬编码密钥/调试代码；
- [ ] 无越权修改；
- [ ] 证据写入 `work/TASK-*-EVIDENCE.md`；
- [ ] 代码审查请求已提交。

## 复盘检查（G5/G7/G8 前，T3/T4）

- [ ] `retro-check` 未到期，或已补 `team/GROWTH.md`；
- [ ] `tasks_at_last_retro` 与 `TASKS.md` 的 `done` 数一致；
- [ ] 问题有 ≥2 次证据；一次性问题在 `RISKS.md`；
- [ ] 提案不直接改 `.opencode/**`；
- [ ] `STATUS.md` 的 `Retro:` 行已更新。

> 到期未做，门禁不得标记通过，也不得开始新的功能任务。

## 提交检查（G5/G7/G8 前，或交接前）

- [ ] `checkpoint-check` 未到期，或已由 DevOps 完成 checkpoint；
- [ ] checkpoint 有 `TASK-GIT-*`、brief 明确路径、`work/TASK-GIT-*EVIDENCE.md`；
- [ ] 工作区未提交文件 < 20，或已提交精选路径；
- [ ] `state/CHECKPOINT.json` 已由 DevOps 用 `--mark` 更新；
- [ ] 没有把 `work/**`、日志、截图、tmp、未脱敏安全报告带进提交；
- [ ] 没有 `git add -A` / `git add .`；Chief 没有自己 commit。

> 到期未提交，门禁不得标记通过，也不得交接。

## 状态一致性检查（会话启动、交接、门禁前）

- [ ] `state-check` 无 error：`PROJECT.md` 与 `STATUS.md` 的 track/stage 一致；
- [ ] `HANDOFF.md` 的 Git/Baseline 等于最近代码 checkpoint；其后的纯文档提交不报 warning；
- [ ] `STATUS.md` 有 `Retro:` / `Checkpoint:` 行；
- [ ] `TASKS.md` 不再新增 `done（...）`；存量迁移到 `review`/`qa`。

> stage/track 不一致时，先修正状态文件；不得交接或把门禁标为通过。

## G5 Verify

### Code Review

- [ ] diff 范围正确；
- [ ] 验收标准逐条对照；
- [ ] 正确性/边界/并发/错误处理；
- [ ] 契约/数据模型一致；
- [ ] 契约 diff 已审查，G4 期间的变更走 ADR/DEC；
- [ ] `API-CONTRACTS` 与错误码/事件枚举恒等，无未登记差异；
- [ ] 修复/回归任务有 P1 closure 表（原 P1、修复点、复现、回归）；
- [ ] 安全基础；
- [ ] 测试有效（断言/确定性/异常覆盖）；
- [ ] 可维护性；
- [ ] 无越权；
- [ ] P0/P1 关闭；
- [ ] 报告写入 `reviews/**`。

### QA

- [ ] 覆盖矩阵完整；
- [ ] 全量基线唯一（命令/总数/skipped/commit），排除项有批准；
- [ ] 单元/集成/契约/E2E 按 Track 执行；
- [ ] 性能/可访问性按 Track；
- [ ] 缺陷有复现/级别/证据；
- [ ] 无未关闭 P0/P1；
- [ ] 回归完成；
- [ ] 测试报告写入 `qa/**`；
- [ ] 环境/版本/commit 记录。

## G6 Secure

- [ ] 威胁模型更新；
- [ ] 认证/授权/租户/IDOR；
- [ ] 输入/输出/注入/SSRF/上传/路径穿越；
- [ ] 密钥/日志/隐私；
- [ ] 依赖 CVE/许可证/lockfile/SBOM；
- [ ] SAST/密钥扫描/IaC/容器；
- [ ] CI/CD 权限/secrets；
- [ ] Critical/High 关闭；
- [ ] Medium 修复计划或书面接受；
- [ ] 报告写入 `security/**`；
- [ ] 放行结论。

## G7 Release

- [ ] CI 全绿；
- [ ] QA 放行；
- [ ] 安全放行；
- [ ] 版本/制品/digest；
- [ ] 数据库迁移/备份；
- [ ] 配置/密钥；
- [ ] 容量/配额；
- [ ] staging 部署 + 冒烟；
- [ ] 回滚命令/数据回滚/演练；
- [ ] 监控/告警/runbook；
- [ ] 生产批准（L3）；
- [ ] 灰度/蓝绿策略；
- [ ] `REL-*` 记录。

## G8 Operate & Retro

- [ ] 发布后健康检查；
- [ ] 监控窗口（按风险 30min–7d）；
- [ ] 错误率/延迟/饱和度；
- [ ] 事故/异常处理；
- [ ] 用户反馈/支持；
- [ ] 完整复盘：做得好/问题/改进/指标；
- [ ] `team/GROWTH.md` 已追加并更新 frontmatter；
- [ ] 遗留项进入 backlog/风险；
- [ ] `HANDOFF.md` 更新。

## 通用“不通过”信号

- 只有口头“完成”，没有命令/证据；
- 测试跳过/只跑 happy path；
- 审查只写“LGTM”；
- 安全只跑工具不看攻击路径；
- 部署没有回滚；
- 文档命令未验证；
- 状态只在聊天里；
- 多个 agent 改同一文件；
- 生产变更没有批准。
