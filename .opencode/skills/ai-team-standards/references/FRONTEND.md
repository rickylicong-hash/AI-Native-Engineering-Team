# FRONTEND — 前端交付检查清单（1.15.0）

> 用法：`变更面` 为 `FE` 或 `full-stack` 的 brief 引用本文件；reviewer/QA 按清单验收。
> 本文件不是新角色，也不绑定框架；项目按自己的路由/组件/测试栈落地。

## 1. 页面与交付面

- [ ] 每个 IA 页面在 `PAGE-MAP.json` 有 `milestone` / `status` / `evidence`；
- [ ] `real` 页面的证据文件存在，且不是 `PlaceholderView` / `AdminUnavailableView`；
- [ ] 未实现页面写 `deferred` + `DEC-*`/`RISK-*` + 复查日期，不能只留占位；
- [ ] 骨架（skeleton）必须写“后端端点合并后接线”的触发条件与 owner；
- [ ] 路由、导航、权限谓词同源；页面直达 URL 有 forbidden/404 兜底。

## 2. 状态与数据诚实

- [ ] loading / empty / error / partial / disabled / 无权限六态齐全；
- [ ] 不用假数据、假按钮、假“已保存”掩盖未实现；
- [ ] “后端未开放”必须能指到缺失端点或 DEC，不写成“暂不可用”了事；
- [ ] 列表分页/筛选/排序有竞态与过期响应守卫；
- [ ] 重试、取消、重复提交、断线重连有确定行为。

## 3. 可访问性与视觉

- [ ] 键盘全流程可达；焦点可见且顺序合理；
- [ ] `aria-live` / `aria-describedby` / 错误摘要与字段关联；
- [ ] 对比度 ≥ 4.5:1（大字 ≥ 3:1），信息不只靠颜色；
- [ ] 触控目标 ≥ 44×44 px；`prefers-reduced-motion` 生效；
- [ ] 亮/暗主题与设计 token 一致；不硬编码颜色/间距；
- [ ] 视觉验收可重复：截图 diff + axe，而不是只靠手工 12 张图。

## 4. 性能与安全

- [ ] 首屏/路由懒加载；无不必要的大包体；
- [ ] 长列表虚拟化或分页；无无界渲染；
- [ ] 输出编码，富文本/工具结果按不可信内容渲染；
- [ ] 不在前端存密钥/令牌；Cookie/CSRF 按契约；
- [ ] 权限隐藏只是体验，服务端仍是最终授权边界。

## 5. 测试

- [ ] 组件/路由/权限/stores 有单元或集成测试；
- [ ] 关键旅程有 E2E（真实后端或契约 mock 明确标注）；
- [ ] a11y 自动检查（axe）纳入 CI；
- [ ] 视觉回归有基线；变更需说明；
- [ ] `typecheck` / `build` / `contrast-check` / `test` 全绿才算可审查。

## 6. 反模式

- 先建占位页，等后端“以后再说”，且没有延期记录；
- 页面写“未开放”，但后端端点已经合并；
- 用全量页面数当分母汇报完成度，掩盖当前里程碑未收口；
- 视觉验收只靠人工截图，无法在 CI 复跑；
- 权限只在前端隐藏，服务端不校验。
