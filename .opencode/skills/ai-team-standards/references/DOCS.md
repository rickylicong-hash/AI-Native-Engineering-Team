# Documentation Reference — Diátaxis / 变更日志 / API 文档

> 基线：Diátaxis、Keep a Changelog、SemVer、Google developer documentation style。

## 1. 四类文档

| 类型 | 读者状态 | 目的 | 不要混入 |
|---|---|---|---|
| Tutorial | 学习 | 手把手跑通 | 大量参考/选项 |
| How-to | 有目标 | 解决具体任务 | 教学铺垫 |
| Reference | 工作中 | 准确查参数/API | 教程/观点 |
| Explanation | 理解 | 讲清为什么/架构 | 步骤清单 |

## 3. API 文档

- 认证/授权方式；
- Base URL/版本；
- 端点：方法/路径/说明；
- 请求：路径/查询/头/体 schema；
- 响应：状态码/schema/示例；
- 错误码/错误体；
- 分页/过滤/排序/限流/幂等；
- 弃用/迁移；
- OpenAPI/AsyncAPI 生成，不手抄。

## 4. 变更日志（Keep a Changelog）

```markdown
# Changelog

## [Unreleased]
### Added
### Changed
### Deprecated
### Removed
### Fixed
### Security

## [1.2.0] - YYYY-MM-DD
...
```

规则：

- 面向用户，不写内部 commit 流水；
- 破坏性变更单独标注 + 迁移步骤；
- 版本遵循 SemVer；
- 链接 issue/PR。

## 5. 运维文档

必须包含：

- 前置/依赖/端口/资源；
- 安装/升级/回滚命令；
- 配置项/默认值/密钥来源；
- 健康检查/冒烟；
- 备份/恢复；
- 监控/告警/日志位置；
- 故障处理/联系链；
- 危险操作警告。

## 6. 写作规则

- 读者优先：开头写“谁/场景/能做什么”；
- 短句、主动语态、具体；
- 命令可复制；前置/预期输出；
- 代码块标语言；
- 术语一致；首次出现给定义；
- 链接用相对路径；锚点有效；
- 图片有 alt；图表用 Mermaid 优先；
- 不写“简单/显然/众所周知”；
- 不写未验证的“支持”；
- 标注版本/平台差异；
- 过期内容删除或标注。
